# 홈택스 부가가치세 자료 수집 1~7

2026년 귀속, 세무대리인 로그인, 거래처별 조회·다운로드를 위한 구현입니다. 첨부 HWP의 본문과 화면 34장, 기존 파이썬, 거래처 엑셀을 분석했습니다. 항목 번호는 이번 요청의 번호를 따릅니다. HWP는 신고도움서비스를 7번으로 나열하지만 이 코드는 요청대로 1번입니다.

**현재 제공물은 실계정 검증 전 실행판입니다.** 입력·업무분기와 로컬 Chromium 시험을 검증했습니다. 실제 홈택스의 로그인 뒤 DOM, 수임 전환, CLIP report 인쇄는 이 환경에서 확인하지 못했습니다. 최초 실행은 `assisted` 모드로 사용하고, 자동 선택에 실패한 항목은 화면에서 설정·확인하여 이어갑니다. 화면 이미지에는 HTML 요소 ID가 없으므로, 검증된 선택자 없이 7개 서비스의 완전 무인 성공을 보장할 수 없습니다.

## 빠른 실행: Windows PC

Python 3.11 이상과 최신 Google Chrome이 필요합니다. PDF로 저장 기능이 작동하는 실제 데스크톱에서 실행하세요. 원래 코드도 Windows 데스크톱용이며, 인증 모듈과 로그인은 사용자가 진행합니다. 본 코드는 Playwright로 Chrome에 연결하므로 Selenium/ChromeDriver/pyautogui 설치가 필요 없습니다.

1. 압축을 한 폴더에 풉니다. 다운로드 결과는 아래 `다운로드` 폴더에 생깁니다.
2. `INPUT-부가세_확장.xlsx`를 엽니다. 원래 거래처 2곳을 유지했고 과세연도 2026, 계산서종류 모두, 매출매입구분 모두를 추가했습니다.
3. `실행_Windows.bat`를 더블클릭합니다. 가상환경/의존성을 설치하고 재시작 가능한 수집 모드로 실행합니다.
4. 새로 열린 전용 Chrome에서 **세무대리인**으로 로그인하고 수임사업자 조회권한을 확인합니다. 일반적으로 쓰던 Chrome 세션과는 별도 프로필입니다.
5. 터미널 안내에 따라 거래처/사업자번호 전체/기간을 대조하고 Enter를 누릅니다. `s`는 해당 작업 건너뛰기, `q`는 종료입니다. 사용자가 확인하지 않은 상태를 성공으로 기록하지 않습니다.
6. 완료 뒤 `다운로드/실행기록.jsonl`과 결과 파일을 확인합니다. 다음에 배치파일을 다시 실행하면 확인된 파일의 해시가 그대로인 성공 작업만 재사용합니다.

직접 실행하는 경우 PowerShell:

```powershell
cd "압축을 푼 폴더"
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe hometax_vat_downloader.py --input "INPUT-부가세_확장.xlsx" --validate-only
.\.venv\Scripts\python.exe hometax_vat_downloader.py --input "INPUT-부가세_확장.xlsx" --resume
```

처음에는 1번으로 확인한 뒤 2~7번을 진행하는 것도 가능합니다.

```powershell
.\.venv\Scripts\python.exe hometax_vat_downloader.py --services 1 --resume
.\.venv\Scripts\python.exe hometax_vat_downloader.py --services 2,3,4,5,6,7 --resume
```

원래 입력파일 그대로 사용하는 방법:

```powershell
.\.venv\Scripts\python.exe hometax_vat_downloader.py --input "INPUT-부가세.xlsx" --year 2026 --resume
```

`--year`는 엑셀에 연도가 없는 경우의 보완값입니다. 엑셀의 과세연도 값이 우선합니다. 비밀번호/인증서 비밀번호/인증번호를 엑셀이나 코드에 넣지 않습니다.

## 항목별 처리

| 번호 | 대상 | 처리 조건과 산출물 |
|---|---|---|
| 1 | 부가가치세 신고도움서비스 | 연도·기수·예정/확정·사업자번호 설정 → 조회 → 전체보고서 PDF |
| 2 | 전자(세금)계산서 합계표조회 | 수임사업자 전환 → 전자세금계산서/전자계산서 각각 매출·매입 → 기간 설정 → 명세서 출력 PDF. 기본 4개 작업 |
| 3 | 신용카드 판매(결제)대행 매출자료 | 결제연도·시작/종료분기 설정 → 인쇄 PDF. 신용카드/대행 등 일부 표가 비어도 전체를 무자료로 판정하지 않음 |
| 4 | 현금영수증 매출총액 | 조회연도·월별 조회. 2기예정이면 7,8,9월 각각 PDF. 화면의 ‘전체’ 선택으로 1년 자료가 섞이지 않게 함 |
| 5 | 매입자납부 특례 | 기본 거래내역조회·품목 전체·매입/매출 전체·적용분기. 엑셀 원본 + 조회화면 증빙 PDF |
| 6 | 수출실적명세서 | 예정=분기, 확정 기본=반기. 파일생성 완료/다운로드 버튼 활성화 확인 → 원본 다운로드 + 보고서 PDF |
| 7 | 내국신용장·구매확인서 전자발급명세서 | 두 서류 각각 연도·기수·예정/확정 조회 → 파일생성 → 다운로드 + 보고서 PDF |

PDF는 보고서 인쇄를 우선 사용합니다. **5번 및 조회 건수가 0인 화면의 PDF는 `조회화면증빙`이라는 별도 이름**으로 저장합니다. 화면 PDF는 그리드의 다른 페이지/스크롤로 숨겨진 전체 거래를 포함한다고 보장할 수 없으며, 공식 보고서 또는 전체 엑셀 원본을 대체하지 않습니다. 1~4번의 Excel 원본 수집은 현재 구현하지 않았습니다. `저장형식=모두`라도 해당 항목은 PDF만 수집하며 실행기록에 이를 표시합니다. 원본만 필요한 경우 1~4를 제외하거나 추가 구현이 필요합니다.

첨부 거래처 2곳의 2026년 2기예정 계획은 거래처당 13건, 총 26건입니다. 이는 **조회계획 수**이며 다운로드 성공 수가 아닙니다. 조회항목과 저장형식에 따라 결과 파일 수는 달라집니다.

## 과세기간 해석

| 입력 | 기본 범위 | 시작일~종료일 |
|---|---|---|
| 1기예정 | 1분기 | 1/1~3/31 |
| 1기확정 | 상반기 | 1/1~6/30 |
| 2기예정 | 3분기 | 7/1~9/30 |
| 2기확정 | 하반기 | 7/1~12/31 |

확정 신고 중 `조회범위=분기`를 선택하면 1기는 4~6월, 2기는 10~12월만 조회합니다. 7번의 첨부 화면에는 확정신고의 분기 단독 선택이 없어서 이 조합은 실행 전에 거절합니다. 7번을 빼거나 반기로 설정하세요. 최종 신고에 사용할 범위는 실제 화면 및 업무 기준과 대조해야 합니다.

현금영수증 화면은 연도+월 선택이므로 월별 PDF로 보관합니다. 자동 합산은 하지 않습니다. 추출 금액을 검증 없이 세금 계산이나 신고서에 반영하지 않습니다.

## 추가 입력 항목

기존 `NO, 사업자명, 대표이사, 사업자등록번호, 과세기간`은 유지했습니다. 대표이사와 NO는 현재 자동조회 키로 사용하지 않습니다. 추가 항목의 필수/선택과 기본값은 `입력항목_요약.md` 및 엑셀의 `입력안내` 시트에 있습니다. 사업자등록번호는 **텍스트 셀**로 저장하고 연도는 명시하세요.

## 인쇄와 다운로드

코드가 새로 실행한 전용 Chrome에는 기본 인쇄 대상을 `Save as PDF`로 설정하고 `--kiosk-printing`을 사용합니다. CLIP report의 인쇄를 통해 PDF가 `다운로드/_incoming`에 만들어지면 이번 실행의 새 파일인지 확인하고 고유 작업 폴더로 옮깁니다. 실제 인쇄 동작은 Windows Chrome에서 최초 확인이 필요합니다.

이미 9222 포트로 실행된 Chrome에 연결했다면, 그 Chrome의 인쇄 설정을 알 수 없으므로 무인 인쇄를 신뢰하지 않습니다. 미리보기에서 **PDF로 저장**을 선택하고 `_incoming`에 저장한 뒤 안내를 따르세요. 자동 저장이 확인되지 않으면 **이번 작업에서 새로 저장한 PDF 경로**를 입력할 수 있습니다. 과거 파일을 성공으로 재사용하지 않습니다.

원본 다운로드는 Playwright의 다운로드 이벤트로 저장하고 PDF는 헤더/페이지 파싱, XLSX는 열기 검사, 파일 공통 SHA-256 검사를 수행합니다. XLS는 형식 헤더를 검사합니다. 이 검사는 파일 손상·HTML 로그인 응답을 잡는 검사이며, 세무 데이터의 모든 숫자나 보고서 거래처/기간 내용이 정확하다는 자동 검증은 아닙니다. 그 내용은 최초 실행의 화면 확인 단계에서 대조해야 합니다.

## 자동으로 설정할 수 없는 경우

홈택스의 WebSquare 컨트롤, 수임사업자 팝업, iframe, 인쇄 버튼은 변경될 수 있습니다. 기본 선택자는 화면에서 확인된 메뉴/라벨/접근성 속성만 이용하고 요소 ID를 임의로 만들지 않습니다. 동일 이름 버튼이 여럿이면 첫 번째를 추측해서 누르지 않습니다.

1. 기본 assisted 모드 안내에 따라 정확한 메뉴·거래처·기간을 직접 설정하여 처리합니다.
2. 선택자를 개선하려면 해당 화면에서 개발자 도구로 요소 ID/CSS를 확인합니다. 아래 명령은 로그인 뒤 현재 화면의 제어요소 메타데이터를 저장합니다. 쿠키·입력값·비밀번호는 수집하지 않습니다.

```powershell
.\.venv\Scripts\python.exe hometax_vat_downloader.py --inspect
```

3. `selectors.example.json`을 `selectors.json`으로 복사하고 실제 확인한 선택자를 입력합니다. 이 예제 파일은 빈 설정입니다. 아래 `#실제_...`는 설명용이며 그대로 사용하면 안 됩니다.

```json
{
  "services": {
    "1": {
      "field:사업자등록번호": {"css": "#실제_사업자번호_ID"},
      "field:과세연도": {"css": "#실제_연도_ID"},
      "field:기수": {"css": "#실제_기수_ID"},
      "search": {"css": "#실제_조회버튼_ID"},
      "result_ready": {"css": "#실제_조회완료_결과영역_ID"},
      "result_identity": {"css": "#실제_결과대상과기간_ID"},
      "report": {"css": "#실제_인쇄하기_ID"},
      "print": {"css": "#실제_리포트인쇄_ID"}
    }
  }
}
```

사용 가능한 키: `menu`, `field:필드명`, `search`, `result_ready`, `result_identity`, `no_data`, `report`, `report_ready`, `report_identity`, `print`, `generate`, `download`. 필요하면 `frame_url_contains`로 프레임 범위를, `index`로 동일 CSS의 컨트롤 순서를 지정합니다. index는 실제 화면에서 위치를 확인한 경우만 사용하세요. `no_data`는 무자료 상황에서만 표시되는 요소여야 합니다. 단순히 항상 존재하는 표를 지정하면 안 됩니다. 수임사업자 전환 모달이 기본 로직과 다른 경우 코드의 `select_client`도 해당 화면에 맞게 보완해야 합니다.

```powershell
.\.venv\Scripts\python.exe hometax_vat_downloader.py --selectors selectors.json --resume
```

`strict` 모드에서는 `result_ready`와 `result_identity`로 결과의 사업자번호·연도·기간·종류를 확인하고, 보고서 인쇄에는 `report_ready`와 `report_identity`도 필요합니다. 이미지/캔버스 보고서는 DOM에서 이를 확인할 수 없어 assisted 모드로 처리해야 할 수 있습니다. strict는 수동 보완을 하지 않으며 입력/결과 검증이 불가능하면 실패로 남깁니다. 현시점에서는 실화면을 검증하기 전 strict 모드의 일괄 성공을 기대하면 안 됩니다.

## 기록과 재시작

- 기존 PDF를 삭제하거나 덮어쓰지 않습니다. 작업별 해시 폴더/실행시각 폴더를 새로 만듭니다.
- `--resume`은 저장 완료·대상 확인 상태·파일 무결성이 모두 유효한 작업만 생략합니다. 각 작업 폴더의 `조회조건.json`에는 대조를 위한 사업자번호와 필터가 로컬 저장됩니다.
- 실패/사용자 건너뛰기/중단은 성공과 구별합니다. 정상 종료=0, 일부 실패=1, 입력·초기화 오류=2, 사용자 중단=130.
- 다운로드에 성공했더라도 나중에 PDF 저장이 실패하면 작업 전체는 실패로 기록할 수 있습니다. 원본 파일은 해당 작업 폴더에 그대로 남아 있으므로 확인하세요. 다음 실행에서는 이 작업을 재시도합니다.
- 작업 도중 메인 탭을 닫거나 다른 작업으로 화면을 바꾸지 마세요. 사용자에게 원래 열려 있던 다른 창은 닫지 않고, 이 실행에서 발생한 팝업만 정리합니다.
- 중단 후 이어서 작업하는 데 필요한 개발 기록은 `이어서_작업.md`에 있습니다.

엑셀·다운로드·Chrome 프로필에는 세무자료/세션이 남습니다. 배포 ZIP에는 사용자 Chrome 프로필이나 다운로드 결과를 넣지 않았습니다. 첨부 거래처가 포함된 확장 엑셀은 본인의 보관 위치에서 사용하세요.

## 개발/테스트

```bash
cd /workspace/hometax_auto
python -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python hometax_vat_downloader.py --validate-only --input INPUT-부가세_확장.xlsx
.venv/bin/python -m pytest -q
```

브라우저 테스트는 `/usr/bin/chromium`을 사용하며 모든 요청을 테스트용 HTML로 대체합니다. 실제 홈택스 요청/로그인/세금 신고를 수행하지 않습니다. Windows에서 브라우저 테스트하려면 tests의 Chromium 실행파일 경로를 설치 위치로 지정하세요. 이 클라우드 환경은 개발·테스트용이며 인증 모듈과 실제 GUI가 필요한 실로그인/인쇄는 사용자 Windows PC에서 확인해야 합니다.
